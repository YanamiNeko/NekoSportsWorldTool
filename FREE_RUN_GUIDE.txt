自由跑使用说明

跑步页面现在有三个路线选项：
1. 经典打卡点环：需要学校打卡点，不需要道路路网。
2. 真实道路路由：需要学校打卡点和道路路网。
3. 自由跑（无打卡点）：不请求学校打卡点，可使用真实道路或本地几何仿真。

运动模型更新：自由跑与真实道路模式共用同一生成器，包含配速变化、弯道预判减速、
步频/步幅联动和 GPS 相关漂移。真实地图有建筑轮廓时，使用同一建筑环境模型。
本地几何仿真已替换原先固定半径圆环，形状随种子变化；不把虚构环境说成真实地图。

使用自由跑：
1. 在“设备信息”保存实际城市、纬度和经度。
2. 在“跑步”的路线算法中选择“自由跑（无打卡点）”。
3. 设置距离、配速和时间。勾选“沿真实道路生成”会按定位获取 OpenStreetMap 道路与建筑。
   也可在“路网”导入本地 OSM 文件，然后切回自由跑。
4. 点击“仅检查/预览（不提交）”，读取学校策略、加载地图并验证路线。
   成功后显示实际采样路线；修改参数或位置后需要重新检查。
5. “开始跑步”会进入提交流程；仅检查和预览不会提交成绩。

自由跑需要学校策略明确返回 freedomRunCalculateSingle=true。
策略含必经点、距离低于最低要求、缺少要求的学校围栏或路线越界时仍会停止。
关闭“沿真实道路生成”时为本地几何仿真，不含实际道路与建筑约束。
启用真实地图后，获取失败会明确报错，不会自动改用虚构路网。
地图下载缓存七天；只向 OpenStreetMap 发送地图范围，不发送学校账号或登录凭据。
自由跑不会把本地几何控制点伪装成学校打卡点。
仅检查/预览不提交成绩、不上传 OBS，也不能保证后续请求被接收或计入考核。

CLI 只读检查并生成本地预览：
  在程序所在目录运行（Windows 使用 .\nekosportsworldtool.exe）：
  ./nekosportsworldtool run --route free --free-roads 1 --dry-run --dist 1.2 --pace 360
  将 --free-roads 1 改为 --free-roads 0 可检查本地几何仿真。
预览文件：
  默认保存到可执行程序所在目录的 run-preview.json，也可用 --out 指定路径。
此文件包含本地生成的坐标和统计，不包含账号密码或登录 token。

诊断当前模式：
  ./nekosportsworldtool diagnose-route
当前配置为自由跑时，不再调用打卡点接口。

本地测试覆盖自由跑无点位准备、原有模式的 10600 错误、围栏/必经点/最低距离限制、
空打卡点数据校验、GUI 选择与配置保存，以及仅连接本机模拟服务器的协议提交测试。
运动模型属于软件仿真，未使用真人运动数据进行统计标定；计分结果以学校平台为准。

成绩显示说明：
“服务端达标判定”直接显示详情接口的 complete 总判定，缺失时显示未知。
reasonList 可能同时包含未通过的点位子项；本工具保留原始明细作为参考，不用子项覆盖总判定。
成绩有效性/审核状态另看服务端 status 与 statusInfo；达标字段和有效性状态分开展示。
可在“运动记录”刷新并打开已有记录详情核对，无需为修正显示而再次提交。
