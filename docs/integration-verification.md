## 已核查的行为

- 违规查询明确区分 `self: null`、字段缺失、格式错误、查询失败和过期状态。显示检查时间、服务端原因；仅明确的正数 `rrid` 能跳转至关联记录。
- 详情响应按记录编号过滤，同一帧收到的旧记录响应不能挤掉当前记录。服务端返回编号不匹配时结束等待并显示错误。
- GUI 禁止任务进行中重复点击。GUI / CLI 使用同一数据目录时，文件锁、持久回执与时间段检查阻止并发或重复跑步提交。
- 响应中断或结果不确定时，只读核对 UUID，不重发成绩或自动补传 OBS；重启后未知状态仍保留。明确拒绝允许用户之后手动重试。损坏、截断或不可写回执会停止提交。
- OBS `laps_json[].avgPace` 从十进制分钟/公里改为秒/公里。1000 米、600 秒、1200 步对应 `avgPace=600.00`、`avgStride=83.33` 厘米；界面含义为 10分00秒/公里。记录级 `speed` 仍为千分之一分钟/公里。
- 配速测试解码实际压缩编码的 OBS 数据，覆盖完整公里、半公里、短尾段、跨公里插值和累计用时；不通过制造随机配速来改变原始统计。
- UI 在 320、360、412 宽度、短屏及桌面布局中模拟滚动和点击；关联记录控件可操作。既有道路刷新、点位、围栏、401 和统计回归包含在完整测试中。

## 结论的适用范围

1. 配速修改依据旧记录截图和源码定位。未通过真实成绩提交核实官方 App 的最终显示；旧服务器记录不会自动改变。
2. 重复提交保护仅覆盖同一数据目录内、本工具保存回执的跑步请求。不覆盖其他独立目录、官方 App、历史无回执记录和 AI 运动。服务器不返回 UUID 或对应记录不在列表时，未知请求不能自动解除。
3. Android 工具链已检查，本机没有可用 JDK、SDK、NDK、adb，未进行 Android 构建或 smoke。macOS 和 Windows MSVC 本轮也未验证。
4. GitHub 的 `windows-road-loop-2026-10-20` Release 和仓库 `downloads/` 中的压缩包是先前道路闭环版本，不包含本批新增修改。源码合并不代表这些包已重新发布。
5. 不宣称 #64 的服务端时间限制、#76 的官方 App 显示或真实服务端计分问题已经全部解决。

## 复现

```sh
cargo test --workspace --locked --offline
cargo test --workspace --no-default-features --locked --offline
cargo check --workspace --all-targets --locked --offline
cargo check --workspace --all-targets --no-default-features --locked --offline
```

需预先准备依赖缓存。Windows 使用 `x86_64-pc-windows-gnu` 目标构建，并在 Windows 本机运行库测试程序；不能仅用交叉编译成功代替本机验证。详细行为说明见[违规状态与重复提交保护](violation-checks.md)和[配速单位修正](pace-unit-fix.md)。
