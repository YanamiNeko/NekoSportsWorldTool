# 违规状态与重复提交保护

本页说明当前源码的违规状态与重复提交保护。2026-10-20 道路闭环 Release 包不包含本批新增改动，版本号保持不变。测试范围见[合并前验证报告](integration-verification.md)。

## 查看违规状态

在「数据 → 违规自查」中点击「立即检查」。GUI 与 CLI 使用同一份服务端查询结果：

- 接口明确返回 `self: null` 时显示「本次查询暂未发现违规记录」。
- 缺少个人状态、格式不符合预期时显示「结果未知」，查询失败时单独显示失败原因。
- 记录检查时间（北京时间）；超过五分钟的查询结果标为过期，需要重新检查。五分钟是本地展示期限，不是服务端规则。
- 有个人违规记录时显示服务端提供的原因和发生时间。字段缺失会明确说明，不推测原因。
- 仅在服务端明确给出正数 `rrid` 时提供「查看关联跑步记录」；通报 `id` 不会被当作跑步记录编号。
- 通报列表显示的是当前页数量，不是全校总数。一次检查结果不保证后续提交有效，也不代表能够避免违规判定。

## 重复提交保护

跑步提交前，会在程序数据目录的 `submission_receipts/` 保存请求回执。GUI 和 CLI 共用该目录，按账号和学校隔离，文件锁阻止两个进程同时为同一账号提交或核对。

回执保存请求 UUID、起止时间和接收/拒绝结果，不保存密码、Token 或轨迹坐标。文件需要写入并同步成功后才发送提交请求。

- 本工具已经收到成功回执的时间段，不能再次提交重叠的跑步记录。
- 网络中断、响应无法解析或成功响应缺少记录编号时，结果属于「未知」。程序只读查询记录列表，用相同 UUID 核对，不会重新发送成绩或自动补传 OBS。
- 未查到相同 UUID 不等于提交失败。未知请求会阻止同账号、同学校的新提交，关闭重开程序也不会解除。
- 可到「运动记录」刷新，或使用 CLI 的记录查询命令继续只读核对。找到唯一对应记录后，会记录其编号；该时间段仍受防重复保护。
- 服务端明确拒绝时，保存拒绝回执，不自动重试；用户之后可手动发起新的请求。
- 回执写入失败、损坏或被截断时停止提交，保留现场以便核对。

保护范围是**同一数据目录中的本工具跑步提交**，不涵盖官方 App、另一份独立数据目录、升级前未保存回执的记录或 AI 运动提交。服务端若不返回请求 UUID，或记录已不在列表中，程序无法自动确认未知请求；本版本不会通过删除回执、等待过期或仅比较距离来解除保护。

这些功能帮助准确呈现状态和减少误操作，不改变服务端规则，也不承诺消除违规。
